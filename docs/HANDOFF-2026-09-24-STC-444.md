## Decisions already made (don't re-ask)

- **Series of PRs**, one slice at a time.
- **JetBrains Mono** for the timecode and lane labels, already bundled in
  `app/renderer/fonts/`. **Silkscreen nowhere in the editor.**
- **Ruler ticks are adaptive:** 1s → 5s → 10s → 30s → 1m, never closer than
  about 6px (scrubber.ts rule 9).
- **`|<` / `>|` are Home/End**, which now go to the trim's in/out points
  (`ScrubState.trimIn/trimOut` in `app/src/scrubber.ts`), and to the take's
  ends when untrimmed. ⇧I/⇧O were rejected because `scrubber.test.ts` pins
  letters as case-insensitive (⇧I marks in).
- **Frame grab:** click copies, ⌥-click saves, and right-clicking the icon or
  the preview opens a Copy frame / Save frame menu. The menu is drawn in the
  page, not a native `Menu`, because the preload bridge has no menu channel.
- **The close (×) icon stays.** The e2e suite closes the editor through
  `#closepreview`, and the editor has no ⌘W binding.
- **Always name the branch when handing off a runbook** (CLAUDE.md, "Hand off a
  runbook WITH its branch").

## Things that will bite

- **The Linux sandbox can't build the Swift helper**, and `vitest.global-setup.ts`
  runs `helper/build.sh`, so `npm test` fails at setup there. To run tests
  anyway, use a throwaway config that clears `globalSetup` and run
  `node app/build.mjs` yourself. Don't commit that config. Run e2e files under
  `xvfb-run -a`.
- **Editor e2e tests are flaky on that sandbox, including on `master`**: 8 of
  62 editor e2e tests failed on master in one run, and 9 on this branch. The
  frame-png tests need the helper, and the export tests hit their 30s
  timeouts. Setup (`openPreview`) sometimes loses the editor page. Get a master
  baseline before blaming a change. macOS CI is the real check.
- **`nativeTheme.themeSource` had no effect under Xvfb.** Screenshots came out
  light either way, so dark mode can't be checked there.
- **Tests read these IDs; keep them:** `#clock` (its textContent must stay
  `current / duration`), `#playpause` (its `aria-label` is `Play`/`Pause`),
  `#scrub`, `#trim-in`/`#trim-out`, `#ticks`, `#triminfo`, `#markin`/`#markout`/
  `#resettrim`, `#openexport`, `#closepreview`, `#framegrab`, `#framestatus`,
  and `#copyframe`/`#saveframe` (now the menu items).
- **Slice 2 has to keep everything in `editor.ts` that reads
  `#timeline.getBoundingClientRect()`.** The pan/zoom span is a CSS transform
  over the full-duration track (see `applySpanTransform`), and every
  frame↔px conversion depends on that. The override blocks (STC-330/331/329)
  sit on the zoom lane and are out of scope for this ticket, but they must
  keep working.
